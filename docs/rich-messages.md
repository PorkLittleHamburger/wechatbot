# 富消息与引用

v0.9.0 支持下述能力。只解析收到的内容，不补读完整微信历史，也不根据截图猜测原文或原图。

## 支持的输入

| 类型 | 交付内容 |
| --- | --- |
| 引用文本 | 引用正文、作者显示名及本地 `reply` ID |
| 链接分享 | 标题、摘要、HTTP/HTTPS URL；用标准文本段保存标题、URL 和摘要，不要求私有字段 |
| 图片 | 优先已缓存原消息；完整引用元数据可交给微信原生下载器接收，校验后注册为媒体 URL |
| 合并转发 | 各条记录的顺序、作者显示名、原时间文本、文本/链接/图片，以及嵌套记录树 |

链接解析不等于抓取网页或视频全文，卡片封面也不冒充原消息图片。图片优先原图，只有标准图时用 `image_quality=standard` 标明；只有缩略图或无可用凭据时返回不可用状态。

## 标准 OneBot 消费方式

引用消息以 `reply` 段上报。`get_msg` 根据本地 ID 返回原消息或引用快照；同账号、同会话的原消息索引优先。快照不会重新触发指令，也不进入普通消息历史。新的有效引用元数据可以补全先前缺失的快照。

合并转发使用 `forward` 段，`data.id` 为网关分配的账号隔离 ID。调用 `get_forward_msg`，传入 `id` 或 `message_id`，得到：

- `message`：标准 `node` 消息段数组，每段的 `data` 包含字符串 `user_id`、`nickname` 和消息段数组 `content`；嵌套内容按原顺序展开，并保留开始/结束边界。只读取标准字段即可取得文字、链接与图片。
- `messages`：为既有接入端保留的 DTO 兼容别名，含 `sender` / `content`；它不是标准节点格式，不作为新集成的前置要求。
- `records`：对应的规范化树，保留层级、作者、原时间文本和消息段。
- `status`：`ready` 或 `partial`；`truncated` 明确标记超限截断。

转发中的显示名不等于经过验证的账号 ID。标准节点 `data.user_id="0"`（兼容别名为 `sender.user_id=0`） 表示没有可靠 ID；不把显示名或其哈希伪装为用户。原时间保留为 `source_time`，无法确认的 Unix 时间用 `0`。AstrBot 自身的解析开关、字数及图片额度仍可能限制送入模型的内容。

## 下载、隔离与边界

图片只走现有的账号绑定原生接收接口，不把引用 XML 的地址交给通用 HTTP 抓取器。下载后检查大小、MD5 和文件类型；超时、校验失败、队列满或切号均不能报告完整成功。部分失败保留其他文字、链接和成功图片。媒体 URL 必须能从接收端环境访问；v0.9.1 会在仅 WS 时复用网关主 HTTP 服务。媒体注册索引持久化于账号媒体目录的 `media.sqlite3`，升级及迁移须保留媒体目录。

解析采用共享额度：转发 XML 小于 256 KiB、最多 200 条记录、嵌套最多 8 层；整个树最多接收 16 张图片、声明总量 64 MiB、单张 20 MiB。达到上限保留已解析部分并标注截断或不可用；没有携带内层内容的远端转发引用不能凭空展开。语音、视频及文件等其他类型保留类型和可用说明，不宣称已下载其正文。

“群聊仅被 @ 时互动”过滤的是外层消息上报。未触发的转发仍可在本地保存以供后续引用；内层出现 `@机器人` 或命令文字不会被重放为新的实时消息。原生引用回复和合并转发发送仍不支持。

出站消息链含 `reply` 时整条返回不支持（`1404`），不会省略引用并返回成功；需要普通发送时由客户端显式提交不含 `reply` 的链。此限制不影响入站引用的 `reply` + `get_msg` 读取。

## 引用故障修复（v0.9.1）

反向 WS 单独启用时，旧版曾生成指向未监听 `onebot.port` 的图片 URL，导致 AstrBot 等接收端连接拒绝，即使图片已接收。本轮改用实际 HTTP 节点或网关主 HTTP 服务的账号隔离媒体路由，并在 `get_msg`、`get_forward_msg` 和历史读取时刷新旧地址。测试包含无管理 Cookie 的真实 HTTP 图片下载；网络连通不代表接收端已把图片交给视觉模型。

解析新增直接 `appmsg/recordinfo`、`recorditem/recordxml/recordinfo` 和内联 `refermsg/content` XML。失败只记录脱敏类别：`missing_container`、`invalid_xml`、`invalid_structure`、`limit_exceeded`，不记录原文、CDN 凭据或密钥。标准正文仍有明确的不可用说明；可选诊断字段不能替代标准消息段。后续简略引用不会覆盖同账号/会话/作者下已完整缓存的转发快照。

**原消息未缓存，且引用只携带卡片、不含记录正文时，目前仍无法凭原生消息 ID 自动补取微信历史或远端转发正文。** 这类情况与解析错误分开报告。可在桥接运行时重新发送完整聊天记录，再引用该条新消息；不能把微信界面能打开记录等同于桥接已获得内层 XML。新增容器测试不证明此前实机失败必然由这些结构遗漏造成，仍需新诊断确认。
